### Общие сведения
Нужна, чтобы определить, как потоки видят изменения в памяти.

Без неё разные процессоры и JVM могли бы по-разному кэшировать переменные или переупорядочивать операции — и многопоточные программы работали бы непредсказуемо.

JMM даёт гарантии:
- Что при использовании volatile или synchronized изменения будут видны другим потокам,
- Что не будет опасного переупорядочения. 

✅ Что делает JMM?
JMM гарантирует, что:

Потоки видят согласованные значения переменных, если используют:
- volatile
- synchronized
- java.util.concurrent (например, AtomicInteger)
- Операции не могут быть переупорядочены в определённых случаях (happens-before).
- Есть чёткие правила для final, volatile, блокировок.

🧱 Почему JMM нужна?
  - Проблема: потоки могут видеть разные значения
```java
int x = 0;
boolean ready = false;

// Поток 1
x = 42;
ready = true;

// Поток 2
if (ready) {
    System.out.println(x); // Что выведется? 0 или 42?
}
```

Без JMM:
- Компилятор может переупорядочить запись (ready = true до x = 42).
- CPU может кэшировать x и ready в локальных кэшах.
- Поток 2 может увидеть ready = true, но x = 0.
- → Непредсказуемое поведение.
