### Общие сведения

Репликация - это процесс копирования данных с одной базы данных (мастер/источник) на одну или несколько других (реплики/слейвы)

#### Цель:
- ✅ Повысить доступность (HA — High Availability)
- ✅ Разгрузить мастер (чтение с реплик)
- ✅ Сделать резервную копию
- ✅ Разместить данные ближе к пользователям (георепликация)

#### Шаги:
1. Мастер записывает все изменения в binary log (binlog).
2. На реплике работает IO Thread — скачивает binlog с мастера.
3. SQL Thread на реплике выполняет эти изменения.
4. Реплика становится точной копией мастера.

#### Типы репликаций
- Тип,Как работает,Плюсы,Минусы
- Асинхронная,Мастер не ждёт подтверждения от реплики,"Быстро, не блокирует",Риск потери данных при сбое
- Синхронная,"Мастер ждёт, пока реплика подтвердит запись",Без потерь данных,"Медленнее, блокировки"
- Семисинхронная,Мастер ждёт хотя бы от одной реплики,Баланс между скоростью и безопасностью,Сложнее настраивать
- Георепликация,Реплика в другом регионе,Ближе к пользователям,Большая задержка (latency)

#### Преимущества репликации
Плюс,Объяснение
- Чтение с реплик,Можно направлять SELECT на реплики — разгружая мастер
- Отказоустойчивость,Если мастер упал — можно перевести реплику в master (failover)
- Резервное копирование,Бэкап с реплики — не нагружает мастер
- Географическая близость,Реплика в Европе для европейских пользователей
- Тестирование,Реплика = точная копия продакшена — можно тестировать

#### Недостатки и подводные камни
- Проблема,Решение
- Задержка репликации (replication lag),Реплика может отставать на секунды/минуты
- Несогласованные данные,Пользователь записал → читает с реплики → не видит свои изменения
- Сложность failover,"Нужно автоматизировать (MHA, Patroni, Orchestrator)"
- Операции DDL медленные,ALTER TABLE выполняется на всех репликах
- Ошибки на реплике,Репликация может остановиться из-за дубликата ключа и т.д.
