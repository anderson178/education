### Общие сведения
Кластеризованный индекс — это не отдельная структура, а сама таблица.

Вторичный индекс - хранится как отдельная структура. В которой хранятся индексированные значения + первичный ключ

### Страницы данных:
Индексы хранятся на диске в виде страниц данных, которые обычно имеют фиксированный размер (например, 16 КБ)

### Размещение на диске:
Индексы размещаются отдельно от самих данных, но связаны с таблицей. Это позволяет оптимизировать скорость поиска, не затрагивая структуру самой таблицы.

### Обновление индексов:
При добавлении, изменении или удалении данных в таблице, индексы также должны обновляться, чтобы поддерживать соответствие между данными и индексами. 
Это может оказывать влияние на производительность операций записи, особенно для больших таблиц с множеством индексов.

### Размер индекса:
Индексы занимают место на диске, и их размер влияет на производительность операций поиска и обновления. 
Меньшие по размеру индексы, как правило, быстрее обрабатываются.

### Сравнение: Кластеризованный vs Вторичный индекс
| Критерий               | Кластеризованный        | Вторичный                      | 
|:-----------------------|:------------------------|--------------------------------|
| Что хранится в листьях | Вся строка              | Значение + PK                  |
| Является ли таблицей   | Да — это и есть таблица | Нет — дополнительная структура |
| Сколько может быть     | Только один на таблицу  | Может быть много               |
| Где используется       | По PRIMARY KEY          | По другим полям (INDEX(email)) |
| PK lookup нужен        | Нет — данные сраз       | Слово → ID строк               |
| Hash                   | Хэш-таблица             | Да — чтобы найти строку        |

### Сводная таблица
| Тип индекса      | Структура              | Что в листьях           | 
|:-----------------|:-----------------------|-------------------------|
| Кластеризованный | B+2Tree                | Вся строка              |
| Вторичный        | B+2Tree                | Значение + PK           |
| Составной        | B+2Tree                | Несколько значений + PK |
| Покрывающий      | B+2Tree                | Нужные поля + PK        |
| Full-Text        | Инвертированный индекс | Слово → ID строк        |
| Hash             | Хэш-таблица            | Хэш(key) → указатель    |


### Пример: Как выполняется SELECT * FROM users WHERE email = 'alice@example.com';
1. БД ищет индекс idx_email.
2. Находит запись: email='alice@example.com' → id=123.
3. Делает PK lookup: идёт в кластеризованный индекс, ищет id=123.
4. Читает страницу с этой строкой (из буферного пула или с диска).
5. Возвращает данные.

### Что такое "страница" (Page)
- Это базовый блок данных, который СУБД читает с диска или записывает на диск.
- Размер: 16 КБ (по умолчанию в InnoDB).
- Одна страница может содержать:
- Несколько строк таблицы.
- Узлы B+Tree (для индексов).
- Служебную информацию (заголовки, указатели на соседей и т.д.).

### Что такое лист (Leaf)
- Это конечный узел B+Tree.
- В нём хранятся реальные данные.

###  Буферный пул (Buffer Pool)
- Это кэш в оперативной памяти, куда загружаются страницы с диска.
- Размер: часто 70–80% от RAM.
- Пока страница в буферном пуле — к ней можно обращаться быстро, не читая с диска.

### PK lookup 
Это обращение к кластеризованному индексу по первичному ключу, чтобы получить остальные данные строки.

Он происходит, когда мы используем вторичный индекс: сначала находим id по индексу, потом по id — всю строку.

Это два поиска, поэтому медленнее, чем поиск по первичному ключу.

Чтобы избежать PK lookup, можно использовать покрывающий индекс, включив в него все нужные поля."
