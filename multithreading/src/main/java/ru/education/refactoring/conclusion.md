### Общие сведения
Улучшение внутренней структуры кода без изменения его внешнего поведения. 

Ситуаци: перед добавлением новой фичи, после написания тестов, в процессе code review и т.д.
### Принципы:
1. Не меняй поведение
2. Пиши тесты до рефакторинга
3. Маленькие шаги
4. Следи за "запахами кода" (code smells)
   - Запах кода,Решение
   - Длинный метод,Вынеси части в отдельные методы
   - Большой класс,Раздели на несколько по ответственностям
   - Дублирование кода,Вынеси в общий метод или класс
   - Слишком много параметров,"Объедини в объект (например, "RequestDTO)
   - Жёсткая связность,"Примени инъекцию зависимостей, интерфейсы"
   - Глобальные переменные / статика,Замени на управляемые зависимости
   - Сложные условия,Вынеси в отдельные методы с говорящими именами
   - Switch/If-лестницы,"Замени на стратегию, полиморфизм, таблицу решений"
5. Используй имена, которые говорят о намерении
6.  Следуй принципам SOLID и GRASP (шаблоны проектирования)
7. Удаляй мёртвый код
8. Упрощай, а не усложняй
